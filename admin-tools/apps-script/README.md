# 앱 안에서 비밀번호 초기화
소유자 Google 관리자만 사용자 관리의 아이디를 펼쳐 비밀번호 초기화를 사용할 수 있습니다.
아이디 자동 입력 → 확인 → 임시 비밀번호 발급. UID와 기존 계정 권한은 유지됩니다.
서버는 Firebase ID 토큰을 Firebase에 조회하여 소유자 이메일·이메일 인증·Google 제공자를 확인합니다. 토큰과 임시 비밀번호는 저장하거나 로그에 남기지 않습니다. 이전 인증 세션은 무효화합니다.

## 기존 초기화 프로젝트 업데이트 (판매·재고 연동 프로젝트가 아닙니다)
1. Code.gs를 이 폴더의 최신 Code.gs로 교체합니다.
2. HTML 파일 Bridge를 추가하고 Bridge.html 내용을 붙여넣습니다.
3. 기존 Reset.html은 최신 파일로 교체합니다.
4. 기존 appsscript.json 및 Firebase IAM 설정은 유지합니다.
5. 배포 → 배포 관리 → 기존 웹 앱 수정 → 새 버전.
   실행 사용자: 나(sonices123@gmail.com). 앱에서 Google 로그인 쿠키 없이 호출하려면 액세스: 모든 사용자.
   공개되는 것은 연결 페이지뿐이며 모든 비밀번호 변경은 서버에서 소유자 Firebase 인증을 요구합니다.
   기존 resetMemberPassword는 private 함수로 변경되어 토큰 없이 호출할 수 없습니다.
6. /exec URL을 앱의 초기화 연결 설정에 입력합니다. 같은 배포 URL이면 다시 입력할 필요 없습니다.
7. 사용자 관리 → 해당 아이디 펼치기 → 비밀번호 초기화. 실제 변경 전 대상 아이디를 확인합니다.

현재 사용자에게 임시 비밀번호를 전달하고 로그인 후 비밀번호 변경을 안내합니다.
로그인 직후 강제 비밀번호 변경은 아직 구현하지 않았습니다.
Apps Script의 iframe 및 Android WebView 동작은 배포 후 실제 환경에서 확인해야 합니다.
비밀번호 변경 결과가 타임아웃되면 사용자가 전달받은 비밀번호로 로그인 가능한지 먼저 확인합니다.
