# SKW 판매현황 연결

원본 Google 시트는 비공개로 유지합니다. 앱은 Firebase 로그인과 보안 규칙으로 허용된 자료만 실시간 구독합니다. PC17760001/PC17760002는 모두 K열 PC1776 자료만, D33654로 시작하는 승인 직원과 소유자는 전체를 봅니다. 직원·판매점 모두 계정 활성 및 판매 권한이 필요합니다.

## 처음 한 번 설정

1. Firebase 콘솔 → Realtime Database → 규칙에서 이 폴더의 **database.rules.json 전체**를 교체하고 게시합니다. 기존 카드 안내, 사용자 승인, 정산 권한 규칙도 포함되어 있습니다.
2. 소유자 Google 계정으로 SKW 판매관리 시트를 열고 원본 탭 이름을 **판매원본**으로 정합니다. 첫 행 제목을 포함해 A~CK열까지 붙여넣습니다.
3. 시트의 확장 프로그램 → Apps Script에서 Code.gs 전체를 이 폴더의 Code.gs로 교체합니다. 기존 비밀번호 초기화 스크립트가 아닌, **판매 시트에 연결된 새 스크립트**입니다.
4. 프로젝트 설정에서 appsscript.json 표시를 켜고 이 폴더의 appsscript.json 전체를 넣습니다.
5. 프로젝트 설정 → GCP 프로젝트 변경에서 **735823287015**를 연결합니다. 소유자가 해당 Firebase 프로젝트의 편집 권한을 가지고 있어야 합니다.
6. 함수 목록에서 **setupSalesSync**를 선택해 실행하고 본인 계정으로 권한을 승인합니다. 웹 앱 배포는 필요 없습니다.
7. 시트를 다시 열면 **SKW 판매 연동** 메뉴가 생깁니다. 연결이 끝나면 앱의 판매 메뉴에서 자료를 확인합니다.

## 이후 사용

판매원본의 이전 원본 내용을 지우고 새 원본을 같은 위치에 제목 포함해서 붙여넣습니다. 새 원본 전체가 기존 판매 자료를 대체합니다. 이력 누적이 필요하면 시트에 보존할 모든 행을 남겨야 합니다. 선택 열만 Firebase로 전송되며 원본 고객명·연락처는 전송하지 않습니다.

붙여넣기는 편집 트리거로 자동 반영됩니다. 파일 가져오기/행 삭제는 변경 트리거로 반영합니다. 다른 프로그램이나 수식으로 변경한 값에는 트리거가 실행되지 않을 수 있으므로 **SKW 판매 연동 → 지금 반영**을 사용합니다.

빈 시트나 형식 오류는 기존 Firebase 자료를 유지합니다. 오류는 Apps Script의 실행 내역에서 확인하고 수정한 뒤 지금 반영을 실행합니다. 완료 시 시트 오른쪽 아래 반영 건수가 표시됩니다. 빈 시트로 전체 삭제하는 기능은 제공하지 않습니다.

담당은 CC열, 유형 필터는 H열 판매채널구분(일반도매/소매 등), 판매처는 CK열을 사용합니다. 개통정보 N열과 약정정보 O열은 별도 표시합니다. 개통시간은 분까지만 표시하며 금액은 숫자 원본일 때 쉼표로 표시합니다.

보안 규칙의 관리자 읽기 권한과 실제 직원/판매점 권한 테스트를 완료한 후 운영합니다. 앱 화면 필터는 접근 권한을 대신하지 않습니다. 브라우저에서는 판매 자료를 쓰지 못하며, 소유자 Apps Script가 OAuth로 동기화합니다. 전송 실패 시 기존 데이터가 보존됩니다.
